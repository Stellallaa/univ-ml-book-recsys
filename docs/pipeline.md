# 데이터에서 평가까지 전체 흐름

원본 데이터가 어떻게 나뉘고, 모델이 무엇으로 학습하고, 무엇으로 채점되는지를 한 장에 정리했습니다. 원본 파일·컬럼 설명은 [`data.md`](data.md)에 있습니다.

## 한눈에 보기

```
원본 평점 (5,976,479건, 독자 53,424명)          책 정보·태그 (books, book_tags)
   │  load_ratings()                              │  load_books(), load_book_tags()
   │                                              │
   │  A4 데이터 분할 load_split()                    │
   ├───────────────────────────────┐              │
   ▼                               ▼              │
일반 독자 48,424명                  신규 독자 5,000명   │
독자 각자의 평점을 시간순으로            (학습에 전혀 안 씀)  │
  앞 70%  = train                cold_tune  2,500명 │
  다음 15% = val                  cold_final 2,500명 │
  마지막 15% = test                         │         │
   │                                      │          │
   │ fit(train) ◀─────────────────────────┼──────────┘ (책 정보를 쓰는 모델만)
   ▼                                     │
학습된 모델 ── score(이력) → recommend → 독자별 추천 10권
   │                                     ▲
   ▼                                     └── 신규 독자는 이력으로 앞 1·3·5·10개만 넣음
정답과 비교 (A5 평가 함수)
```

## 1. 데이터 불러오기 (A3)


| 함수                 | 돌려주는 것                                        |
| ------------------ | --------------------------------------------- |
| `load_ratings()`   | 평점 `user_id, book_id, rating`. 파일 순서(시간순) 그대로 |
| `load_to_read()`   | 읽고 싶은 책 `user_id, book_id`                    |
| `load_books()`     | 책 정보 (제목, 저자 목록, 대표 저자, 출판연도 등)               |
| `load_book_tags()` | 책별 태그 `book_id, tag_name, count`              |


정리 규칙은 [`src/bookrec/data/README.md`](../src/bookrec/data/README.md)에 있습니다.

## 2. 평점 나누기 (A4)

`load_split()`이 평점을 다섯 표로 나눕니다. 나누는 대상은 평점뿐이고, 책 정보·태그·to_read는 나누지 않습니다.

```
일반 독자 한 명의 평점 (시간순)
0% ──────────── 70% ───── 85% ───── 100%
│     train      │   val   │   test  │
```


| 표            | 무엇                  | 언제 쓰나                        |
| ------------ | ------------------- | ---------------------------- |
| `train`      | 일반 독자 각자의 앞 70%     | 모델 학습                        |
| `val`        | 다음 15%              | 설정 고르기 (튜닝)                  |
| `test`       | 마지막 15%             | 고른 설정으로 최종 점수를 **한 번** 잴 때   |
| `cold_tune`  | 신규 독자 2,500명의 평점 전부 | 신규 독자 상황에서 설정 고르기            |
| `cold_final` | 신규 독자 2,500명의 평점 전부 | 신규 독자 상황의 최종 점수를 **한 번** 잴 때 |


- 신규 독자 5,000명은 나누기 전에 무작위로 먼저 뺍니다. 이 사람들의 평점은 어떤 모델의 학습에도 들어가지 않습니다.
- 일반 독자는 사람마다 따로, 자기 평점의 앞 70%·15%·15%로 나눕니다. 과거 기록으로 미래를 맞히는 상황을 만들기 위해서입니다.
- 누가 언제 불러도 같은 결과가 나옵니다(무작위 시드 고정).

## 3. 모델 학습과 추천

모든 모델은 공통 형태(`src/bookrec/models/base.py`)를 따릅니다.


| 단계    | 함수                    | 하는 일                                       |
| ----- | --------------------- | ------------------------------------------ |
| 학습    | `fit(train)`          | `train` 표로 학습합니다                           |
| 점수    | `score(이력)`           | 독자의 평점 이력을 받아 책 1만 권 각각에 점수를 매깁니다          |
| 추천    | `recommend(이력, k=10)` | 점수가 높은 순으로, 이미 읽은 책(기본은 이력)을 빼고 10권을 고릅니다 (공통 코드) |
| 별점 예측 | `predict(쌍)`          | (독자, 책) 쌍의 별점을 예측합니다. 별점으로 답하는 모델만         |


- 설정을 고르는 동안 평점을 쓰는 학습은 **`train`으로만** 합니다. `test`와 신규 독자의 평점은 언제나 학습에 넣지 않습니다.
- 책 정보·태그는 평점이 아니라서 나누지 않고 그대로 씁니다.

## 4. 채점

학습과 채점에서 모델에 무엇을 넣고 무엇과 비교하는지는 아래와 같습니다. 채점은 A5 평가 함수(`bookrec.evaluation`)가 하고, 사용법은 [`src/bookrec/evaluation/README.md`](../src/bookrec/evaluation/README.md)에 있습니다.


| 단계                    | 넣는 것                                                         | 나오는 것         | 비교 대상                                 | 비고                                                                                                       |
| --------------------- | ------------------------------------------------------------ | ------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 학습 `fit(train)`       | 일반 독자 48,424명의 `train` 데이터 (user\_id, book\_id, rating)      | 학습된 모델        | -                                     | `train` 데이터 중 어떤 컬럼을 사용할지는 모델마다 다릅니다.<br>- collaborative filtering은 세 컬럼 모두 사용<br>- 인기순은 `book_id`만 사용 등 |
| 별점 평가 `evaluate_rmse` | 일반 독자 48,424명에 대한 `test` 데이터 (user\_id, book\_id)             | 유저별 도서의 예측 별점 | `test`의 실제 별점                         | 별점을 예측하는 모델(MF, bias 기준선)만 평가 가능                                                                        |
| 추천 평가 `evaluate_warm` | 일반 독자 48,424명에 대한 `train` 데이터 (user\_id, book\_id, rating)   | 독자별 추천 10권    | 그 독자가 `test`에서 4점 이상 준 책, to\_read 목록 | 이력은 독자가 누구인지와 이미 읽은 책을 알려 줍니다                                                                            |
| 추천 평가 `evaluate_cold` | 신규 독자 2,500명 각자의 앞 1·3·5·10개 평점 (user\_id, book\_id, rating) | 독자별 추천 10권    | 11번째 평점부터 4점 이상 준 책, to\_read 목록      | 학습에 없던 독자라 이력이 그 독자에 대한 유일한 정보입니다.<br>넣는 이력이 1·3·5개여도 앞 10개 책은 이미 읽은 책으로 쳐서 추천에서 뺍니다                                                                        |


- 설정을 고를 때(튜닝)는 위 표의 `test` 자리에 `val`을 넣습니다. 최종 채점(`test`)에서 `evaluate_warm`의 이력은 `train` + `val`입니다.
- 두 추천 평가 모두 모델에 넣는 형태는 같은 이력 표(user_id, book_id, rating)입니다. 행 수만 다릅니다(기존 독자는 `train` 기준 평균 약 78개, 신규 독자는 1·3·5·10개). 이력은 학습에 이미 쓴 데이터이거나 학습에 없던 신규 독자의 것이고, 채점 구간의 평점은 넣지 않습니다.
- 최종 채점 전에 고른 설정으로 `train` + `val`을 다시 학습할지는 모델 담당자가 정합니다.

기존 독자 채점에서 넣는 것과 정답을 나란히 놓으면 아래와 같습니다.


|                 | 넣는 것 (X)        | 나오는 것              | 정답 (Y)                         | 지표                               |
| --------------- | --------------- | ------------------ | ------------------------------ | -------------------------------- |
| 별점 평가           | (독자, `test`의 책) | 예측 별점              | `test`의 실제 별점                  | RMSE                             |
| 추천 평가 ① 좋아한 책   | 독자 (이력으로 넘김)    | 추천 10권             | 그 독자가 `test`에서 4점 이상 준 책       | Precision@10, Recall@10, NDCG@10 |
| 추천 평가 ② 읽고 싶은 책 | 독자 (이력으로 넘김)    | 추천 10권 (①과 같은 10권) | 그 독자의 to\_read 목록 (이미 읽은 책 제외) | to\_read 적중                      |


- 추천은 한 번만 받습니다. 같은 10권을 정답 두 가지와 각각 비교합니다.

**누구에게** 추천하는지(목표)와 **무엇을 정답으로** 볼지(평가 기준)를 나눠서 채점합니다.


| 목표           | 질문                                              | 넣는 이력                              |
| ------------ | ----------------------------------------------- | ---------------------------------- |
| Goal 1 신규 독자 | 평점이 1·3·5·10개뿐인 사람에게도 잘 추천하나? 평점이 늘수록 얼마나 나아지나? | 신규 독자의 앞 1·3·5·10개 (네 번 따로)        |
| Goal 2 기존 독자 | 기록이 충분한 사람에게 정확히 추천하나?                          | `train` (최종 채점 때는 `train` + `val`) |



| 평가 기준   | 정답                                                                         | 지표                               | Goal 1 | Goal 2 |
| ------- | -------------------------------------------------------------------------- | -------------------------------- | ------ | ------ |
| 좋아한 책   | Goal 1: 11번째 평점부터 4점 이상 준 책<br>Goal 2: `val`(튜닝) 또는 `test`(최종)에서 4점 이상 준 책 | Precision@10, Recall@10, NDCG@10 | O      | O      |
| 읽고 싶은 책 | 그 독자의 to\_read 목록 중 이미 읽은 책(Goal 1은 앞 10개, Goal 2는 넣은 이력)을 뺀 책                                            | to\_read 적중 비율                   | O      | O      |
| 실제 별점   | `val`(튜닝) 또는 `test`(최종) 구간의 실제 별점                                          | RMSE (별점을 예측하는 모델만)              | -      | O      |


- **Goal 1은 모델 하나에 이력만 바꿔 넣습니다.** 1·3·5·10개 네 경우 모두 같은 정답(11번째 평점부터)으로 채점해야 "평점이 늘수록 나아지는지"를 비교할 수 있습니다.
- **최종 채점의 이력에 `val`을 넣는 이유:** `test`는 `val`보다 나중이라, 그 시점의 독자는 `val`의 책을 이미 읽은 상태입니다.
- 지표는 독자마다 계산한 뒤 독자들의 평균을 냅니다. 정답이 하나도 없는 독자는 그 지표의 평균에서만 빠집니다.
- 모든 결과는 기준선(A6: 인기순, Goodreads 평점순, bias)과 함께 보여 줍니다.

## 5. 지켜야 할 것


| 규칙                                 | 이유                                     |
| ---------------------------------- | -------------------------------------- |
| 데이터를 각자 나누지 않고 `load_split()`을 씁니다 | 모든 모델이 같은 데이터로 비교되어야 합니다               |
| 설정은 `val`·`cold_tune` 점수로만 고릅니다    | `test`·`cold_final`로 고르면 최종 점수가 부풀려집니다 |
| `test`·`cold_final`은 마지막에 한 번만 잽니다 | 처음 보는 데이터에서의 실력을 재기 위해서입니다             |
