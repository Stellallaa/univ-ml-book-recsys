역할

업무 간 의존성

열은 의존 단계(앞 열의 작업이 끝나야 다음 열을 시작), 행은 역할입니다. 굵은 선은 일정을 좌우하는 핵심 사슬(주경로)입니다. 카드에 마우스를 올리면 설명이 뜨고, 클릭하면 설명이 고정되며 그 작업의 선행·후행 작업만 남습니다.

위 그래프의 순서를 지키도록 배치했습니다. 회색 열은 주말, 굵은 세로선은 관문입니다. 막대도 마우스를 올리거나 클릭하면 설명이 보입니다.

주경로 작업병행 같은 사람이 동시에 진행

모두가 신경 쓸 것

  • 코드에 주석을 적극 활용합니다. 참고한 외부 코드·자료는 출처를 기록해 두었다가 PPT 마지막 레퍼런스에 모읍니다.* 텀프로젝트 공지 교안 필수사항 (7쪽: 주석, 외부 코드 출처 표기)
  • 수업에서 다루지 않은 라이브러리·함수는 파라미터까지 설명합니다.* 텀프로젝트 공지 교안 필수사항 (7쪽)
  • 모든 모델은 A2에서 정한 공통 형태를 따릅니다. 그래야 같은 평가 코드와 hybrid에 그대로 넣을 수 있습니다.
  • 데이터는 A4에서 나눈 파일만 쓰고, 각자 따로 나누지 않습니다. 각자 나누면 모델끼리 비교할 수 없고, 신규 독자 실험용 독자가 학습에 섞일 수 있습니다.
  • 튜닝은 검증 데이터로만 하고, 평가 데이터는 최종 결과를 잴 때만 씁니다. 평가 데이터로 설정을 고르면 점수가 부풀려집니다.
  • 실험할 때마다 설정과 점수를 기록해 둡니다. 결과가 나빠도 남깁니다. 비교표와 발표의 결과 분석 재료가 됩니다.* 텀프로젝트 공지 교안 요구사항 (6쪽: 성공·실패와 관계없이 결과 설명)
  • 그래프는 A1의 공용 그래프 함수로 저장합니다. PPT에 들어갈 그래프의 폰트·크기·색이 같아집니다.
  • PR은 다 같이 리뷰할 수 있도록 합니다.
  • 의사결정이나 구현에 관한 질문은 GitHub Issue로 주고받습니다. 논의 히스토리를 남기기 위해서입니다.
  • PPT 제작을 위해 각자 작업 내용을 팀원 A가 만든 폴더에 md로 정리합니다. 그래프·이미지도 같은 폴더에 함께 정리해 둡니다.
